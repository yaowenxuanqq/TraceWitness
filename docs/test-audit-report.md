### P0-02：`run_eval.bat` 无法完成一键评测

**严重级别：** P0，验收阻塞  
**实测结果：** 命令退出码为 1。

**根因：**

1. 从仓库根执行 `platform\gradlew.bat test`，Gradle 把根目录当成项目目录，报错“does not contain a Gradle build”。
2. 脚本先设置相对路径 `PY=ai-service\.venv\Scripts\python.exe`，再 `pushd ai-service`，进入子目录后该相对路径失效。
3. 评测失败后仍继续生成报告。
4. Gradle 失败时仍可能读取上次遗留的 `platform/build/test-results/test`，导致报告出现“Gradle 退出码 1，但测试方法 25，失败 0”的矛盾结果。

**影响：**

- 用户无法通过一次命令完成正式验收。
- `docs/eval-report.md` 和 `docs/resume.md` 可能包含陈旧或不完整的数据。
- 一键评测结果不能作为简历或项目交付的可靠证据。

**解决方案：**

1. Gradle 改为：

```bat
pushd "%REPO%\platform"
call gradlew.bat clean test
set GRADLE_EXIT=%ERRORLEVEL%
popd
```

或从仓库根执行：

```bat
call platform\gradlew.bat -p platform clean test
```

2. Python 使用绝对路径：

```bat
set "PY=%REPO%\ai-service\.venv\Scripts\python.exe"
```

3. 评测前删除旧结果目录，避免读取陈旧 XML：

```bat
if exist "%REPO%\platform\build\test-results" rmdir /s /q "%REPO%\platform\build\test-results"
```

4. 将 Gradle、pytest、benchmark、报告生成四个退出码全部纳入最终判断。
5. 报告生成器必须校验本次运行标记，不能读取缺失或过期的测试结果。
6. 在干净目录或新的 Git clone 中重新执行完整评测。

**完成标准：**

- 在干净 clone 中运行 `run_eval.bat` 返回 0。
- Gradle、pytest、benchmark 和报告退出码全部为 0。
- `docs/eval-report.md` 中的测试数量、失败数和退出码来自同一次运行。

### P0-03：`run_mock.bat` 启动链路错误

**严重级别：** P0，演示阻塞  
**证据：**

```bat
start "tracewitness-platform" /D "%REPO%" cmd /c "platform\gradlew.bat bootRun"
```

该命令在仓库根启动 Gradle，但没有指定 `-p platform`，与 `run_eval.bat` 的错误相同。

**其他问题：**

- 脚本不设置 `JAVA_HOME`。
- 本机 `JAVA_HOME` 指向 Java 21，而项目按 Java 8 构建。
- Gradle 优先使用 `JAVA_HOME`，不是 PATH 中的 `java`。

**影响：**

- 双击演示脚本可能直接失败。
- 不同机器可能使用不同 JDK，导致“本机能跑、换机失败”。

**解决方案：**

1. 将平台启动改为：

```bat
start "tracewitness-platform" /D "%REPO%\platform" cmd /c "gradlew.bat bootRun"
```

2. 在脚本中检测 Java 主版本，要求 Java 8。
3. 支持从常见安装路径发现 Java 8，例如 `JAVA_HOME_8`、Adoptium 目录或 `where java`。
4. 找不到 Java 8 时立即给出明确错误，不继续启动。
5. 文档同步说明 `JAVA_HOME` 必须指向 Java 8。

**完成标准：**

- 在 PATH 和 `JAVA_HOME` 都指向 Java 8 时启动成功。
- 在 `JAVA_HOME` 指向 Java 21 时脚本给出明确错误或自动切换到 Java 8。
- `http://127.0.0.1:8080/api/health` 和 `http://127.0.0.1:8000/health` 均返回 200。

### P1-02：JSON Schema 没有真正执行

**严重级别：** P1，高  
**证据：**

- `contracts/agent-report.schema.json` 设置了 `additionalProperties: false`。
- Python `validate_report` 遇到额外字段时不会拒绝，而是静默丢弃。
- 工具参数包含额外字段时仍会继续传递。
- 实测：

```json
{"unexpected": "accepted?"}
```

被静默丢弃，没有报错。

**影响：**

- 项目宣传中的“JSON Schema 约束”与实际行为不一致。
- 模型可能输出拼写错误或恶意额外字段，系统不会 fail closed。
- 工具参数类型和必填项没有统一验证。

**解决方案：**

1. Python 增加 `jsonschema` 依赖，报告和工具参数都使用正式 schema 校验。
2. Java 执行工具前再次校验参数，防止绕过 Python 服务。
3. 对未知字段、错误类型、缺失必填项、非法枚举统一拒绝。
4. 增加契约测试：
   - 合法报告通过
   - 多字段失败
   - 缺字段失败
   - 类型错误失败
   - 非法工具参数失败
5. 校验失败时记录结构化错误，不允许静默修正后继续。

**完成标准：**

- 所有 Agent 输出通过 `agent-report.schema.json`。
- 所有工具参数通过 `contracts/tools/*.schema.json`。
- 额外字段和错误类型会被拒绝。

### P1-03：Java 服务默认暴露到局域网且写接口无认证

**严重级别：** P1，安全  
**证据：**

- `Get-NetTCPConnection` 显示 Java 监听地址为 `::`，即所有网卡。
- 从局域网地址 `172.23.208.1:8080` 和 `192.168.110.27:8080` 均能访问 `/api/health`。
- 审批、告警确认、难例标注、插件回滚等 POST 接口没有认证。
- `actor` 来自请求体，客户端可任意填写。

**影响：**

- 同一局域网内其他设备可以调用变更接口。
- 审计记录中的操作者身份不可信。
- 项目当前只能安全绑定到本机回环地址。

**解决方案：**

1. 在 `application.yml` 增加：

```yaml
server:
  address: 127.0.0.1
```

2. 如果确实需要局域网访问，增加认证、授权和 CSRF 防护。
3. `actor` 从认证主体读取，不从请求体接收。
4. 生产模式禁用默认 H2 密码为空和 `error.include-message: always`。
5. 增加启动安全检查：非回环地址且无认证时拒绝启动。

**完成标准：**

- 默认仅 `127.0.0.1:8080` 可访问。
- 局域网 IP 无法访问。
- 所有变更接口都需要可信身份。

### P1-04：移动端布局不可用

**严重级别：** P1，高  
**证据：**

- 390 × 844 视口下，文档宽度为 407，横向溢出 17 px。

**完成标准：**

```text
document.documentElement.scrollWidth <= innerWidth
```

- 事件和检索区域无横向滚动。
- 主要按钮可点击。
- 长 ID 不逐字符换行成竖排。
