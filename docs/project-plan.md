# TraceWitness 项目计划书 v0.4

**Project：** TraceWitness  
**GitHub Repository：** `TraceWitness`  
**Subtitle：** AI-Native Video Incident Investigation Agent  
**文档版本：** v0.4  
**修订日期：** 2026-11-10  
**计划周期：** 12 周  
**投入假设：** 每周约 20 小时  
**目标环境：** Windows 11、16GB 内存、无独显、非管理员权限  
**默认部署：** Java + Python 双进程 + H2 + 本地文件 + 浏览器  

> v0.4 在 v0.3 基础上明确“软件仿真优先、真实硬件零依赖”。项目目标是形成可执行、可评测、可公开的纯软件 Agent 平台；Mock 只是降级模式，真实本地 LLM 是 Agent 验收条件。

## 1. v0.4 修订摘要

1. **确定真实 LLM 路径**
   - 默认本地 Qwen2.5-3B-Instruct GGUF Q4_K_M + llama.cpp。
   - 可选 OpenAI-compatible 云 API。
   - Mock 只作为离线降级，不作为首版 Agent 验收路径。

2. **第 6 周拆周**
   - 第 6 周只做端云路由。
   - 第 7 周只做 Agent 主链路。
   - 人员档案后移第 8 周。

3. **跨进程虚拟时钟**
   - Java 为评测模式权威时钟。
   - Python 使用调用方注入的时间戳。
   - 禁止 Python 自行生成业务时间。

4. **评测增量建设**
   - 第 6 周先写 10 条反向断言。
   - 第 7-10 周累计 30 正向 + 20 反向。
   - 第 11 周只跑分和加固。

5. **Agent 引用校验可执行化**
   - 结构化输出强制 `source_ids`。
   - 只允许引用本次 run 实际返回过的 ID。
   - 失败重试一次，再失败降级为证据不足。

6. **P1 分层**
   - P1a：AOR、非机动车。
   - P1b：插件、电量、安全域。
   - 明确砍单顺序。

7. **文档与交付前移**
   - README、架构、API 文档骨架第 9-10 周完成。
   - 第 12 周只做集成、评测、录屏和公开检查。

8. **软件仿真边界**
   - 不接入真实摄像头、门禁、梯控、边缘盒或厂商硬件 SDK。
   - 设备、遥测、门禁事件和联动动作均由确定性模拟器产生。
   - RTSP 仅作为可选软件测试流；默认输入为本地视频文件。
   - 端侧资源、电量、安全域、低功耗和曝光只做软件策略仿真。

## 2. 项目定位

### 2.1 对外定位

> 面向视频安防场景的事件调查 Agent 平台，支持结构化视频分析、端云复核、自然语言调查、时空检索和可核验证据导出。

### 2.2 项目目标

- 形成 AI 应用开发作品
- 形成 Java 全栈作品
- 形成真实 Agent 工具调用与评测作品
- 形成可复现、可公开、可面试讲述的项目

### 2.3 不做什么

- 不还原公司原产品源码
- 不连接真实摄像头、门禁、梯控、边缘计算盒或其他物理设备
- 不接入厂商硬件 SDK、私有协议、固件或硬件管理接口
- 不做真机固件、ISP、NPU、PMIC、射频
- 不做生产级人脸识别系统
- 不做 11 个平均浅层 Demo
- 不做只有聊天框的伪 Agent
- 不做依赖 Docker 才能启动的演示

## 3. 环境与部署

### 3.1 默认环境

- Windows 11
- 16GB 单通道内存
- 无独显
- 非管理员权限
- 用户级 Java 21、Python 3.11、Node 仅开发构建需要

### 3.2 默认运行形态

```text
浏览器
  │
Java Spring Boot
  ├─ H2 文件数据库
  ├─ 本地媒体/证据目录
  ├─ 进程内事件队列
  ├─ Outbox
  └─ 前端静态资源
  │
Python 单进程
  ├─ ONNX 推理
  ├─ llama.cpp 本地 LLM
  ├─ Agent 编排
  ├─ Tool API
  └─ 评测
```

### 3.3 启动与降级

- `run_demo.bat`：真实模型演示
- `run_mock.bat`：模型或数据缺失时降级
- `run_eval.bat`：固定场景评测
- 端口检查、错误 `pause`、`%~dp0` 定位
- 不要求 Docker
- 不要求在线地图
- 不要求 GPU
- 不要求云 API
- 不要求任何真实硬件

### 3.4 存储策略

- 元数据：H2 文件库
- 图片/短视频/证据：本地目录
- 异步事件：进程内队列 + Outbox
- Agent 状态：数据库
- 向量检索：Python 内存 NumPy
- 地图：自绘点位示意图，不接在线瓦片
- 后续可替换 PostgreSQL、MinIO、RabbitMQ、pgvector

### 3.5 软件仿真边界

- 项目交付形态为纯软件系统，真实硬件依赖为零。
- 默认视频源为本地合成或已授权样例文件。
- 可选 RTSP 只连接本机软件 RTSP 服务，用于协议适配验证，不作为验收必需项。
- 摄像头、NVR、门禁、梯控、边缘盒、设备电量、安全域和曝光均由 `device-simulator` 生成状态与事件。
- 门禁、梯控动作只生成模拟审批请求和审计记录，不产生物理控制。
- 性能指标只代表开发机上的软件推理性能，不代表端侧芯片性能。

## 5. 成功指标

### 5.1 演示标准

- 5～10 分钟完成一条从视频事件到调查报告的链路
- 真实 LLM 完成意图理解、工具选择和报告生成
- 关键结论引用真实事件/证据 ID
- 插件或策略至少有一个失败回退演示

### 5.2 指标

| 指标 | 目标 | 验证方式 |
|---|---|---|
| 单路 1080p 软件视频输入检测 | 降采样 640 后 ≥5 fps | 性能脚本 |
| 4 路 1080p 软件视频输入并发 | 每路检测采样 ≥2 fps | 性能脚本；不满足则声明离线模式 |
| 1 万条向量检索 | P95 <1 秒 | `run_eval.bat` |
| Agent 正向任务完成率 | ≥85% | 30 正向场景 |
| Agent 反向安全断言 | 100% 通过 | 20 反向场景 |
| 工具选择准确率 | ≥85% | 正向场景 |
| 引用合法率 | 100% | 引用校验器 |
| 确定性业务决策重放 | 100% 一致 | 重放测试 |
| 插件回滚 | 60 秒内 | 故障注入 |
| 证据包校验 | 100% | 自动校验 |

### 5.3 非确定性来源

以下不要求完全一致，但必须记录：

- 真实网络延迟
- 云端 API 响应内容
- LLM 自然语言措辞
- 第三方模型内部浮点差异
- 真实墙钟抖动

业务决策必须使用固定输入和快照，不依赖不可控因素。

## 6. 真实 LLM 与 Agent 策略

### 6.1 模型适配器

统一接口：

```text
ModelAdapter
├─ LocalLlamaAdapter
├─ OpenAICompatibleAdapter
└─ MockAdapter
```

### 6.2 默认本地模型

- Qwen2.5-3B-Instruct GGUF Q4_K_M
- llama.cpp / llama-cpp-python
- temperature=0
- 固定 seed
- 固定 system prompt 与工具 schema
- 记录模型文件哈希、量化版本和推理参数

本地模型必须能完成：

1. 任务意图解析
2. 选择一个或多个工具
3. 基于工具结果生成结构化报告

### 6.3 Mock 定位

Mock 只用于：

- 无模型文件
- 内存不足
- CI
- UI 联调

Mock 运行时必须显示 `MOCK_MODE`，不得计入 Agent 真实指标。

### 6.4 Agent 工具

P0 工具：

1. `search_events`
2. `get_event_detail`
3. `search_person`
4. `build_trajectory`
5. `find_companions`
6. `export_evidence`

P1 工具：

- `get_device_status`
- `create_review_ticket`
- `simulate_device_action`

### 6.5 引用校验机制

Agent 输出必须符合 JSON Schema：

```json
{
  "conclusion": "string",
  "source_ids": ["event-id", "evidence-id"],
  "confidence": 0.0,
  "insufficient_evidence": false,
  "requested_actions": []
}
```

校验规则：

1. `source_ids` 必须是本次 `run_id` 内工具实际返回过的 ID。
2. 跨 run 引用无效。
3. 空引用结论只允许标记为“证据不足”。
4. 校验失败：重试一次，并提示上次引用非法。
5. 第二次失败：返回“证据不足，无法结案”。
6. 记录 `citation_invalid`、`tool_failed`、`model_failed` 等失败类型。

### 6.6 高风险动作

- 门禁、梯控等动作只能生成审批请求。
- 必须有人工确认记录。
- Agent 不得直接执行。

## 7. 确定性工程

### 7.1 统一时间源

- Java 持有权威 `TimeSource`
- Python 业务时间由 Java 调用时注入
- 评测模式从 `run_manifest.json` 读取 `epoch_start` 和 `tick_ms`
- 所有事件、轨迹、插件健康、Agent 超时使用同一时间基准

### 7.2 跨进程时间规则

- Java 调 Python 必须传 `request_timestamp`
- Python 返回结果不得自行生成业务时间戳
- Java 写入事件时间、推理耗时和决策时间
- 两端记录相同 `run_id` 和 `clock_mode`

### 7.3 固定输入

- 视频
- 推理模型版本
- 策略版本
- 场景脚本
- 随机种子
- 并发输入 `q_scripted`
- 虚拟时钟
- LLM 参数

### 7.4 双轨并发

- 真实模式：`q_observed`
- 评测模式：`q_scripted`
- 决策审计同时记录 `q_observed`、`q_input`、`theta_u_eff`

### 7.5 决策快照

覆盖：

- 结构化/回退
- 端云上送
- 档案合并
- 轨迹可达
- 插件回滚
- Agent 工具选择
- 人工审批

### 7.6 结果精度

- 中间计算 ≥4 位
- 落库 2 位
- 单测容差 ±0.005
- 距离、速度、相似度统一工具类

- JSON + 小图

1. 门控失败：优选时刻整帧。

- 决策快照

- 低质量人脸不得建新档
- 签名失败不得加载插件
- 高风险动作必须人工确认
- 未知业务不得走公网
- 证据文件缺失必须报错

- 先写断言再实现
- 场景独立存放
- 预留 10 个回归场景，不在开发中反复调参
- 报告展示失败项
- 所有数字由 `run_eval.bat` 生成

## 19. 结论

v0.4 的执行底线：

1. **没有真实 LLM，不算 Agent。**
2. **没有引用校验，不算可追溯 Agent。**
3. **没有反向评测，不算可信评测。**
4. **第 6 周不做完端云路由，就砍 P1b。**
5. **第 12 周只交付，不加功能。**

12 周后应交付的不是“11 个功能都有一点”，而是：

> 一条真实、可重复、可解释、可公开的视频事件调查 Agent 链路。
